# Buyline: AI procurement agent (Fo track)
Tell it what to buy. It calls suppliers through Fo, extracts quotes, catches traps (minimum order, lead time, budget), negotiates with the best rival price, and writes the PO.

Run (from this folder; the repo venv has the SSL certs and the key comes from ../.env):
```
../.venv/bin/python orchestrate.py "500 m of 12AWG copper wire, within two weeks, budget $500, ship to Berkeley CA" --pause 2
python3 serve.py                                 # dashboard + Approve buttons on http://localhost:8020/
```
- Two links: `BUYLINE_MODE=sample python3 serve.py 8020` is the public one (any item, e.g. 'metal bars': canned sample calls written for that item, labelled 'sample call', no phone, no prerun). `BUYLINE_MODE=live python3 serve.py 8030` is the demo one (real Fo to the test phone, quote calls replayed from prerun.json). `BUYLINE_FO` overrides the Fo mode.
- `--fo stub|sample|dry|live`. stub (default) answers from `--replies FILE` (see replies.example.json: suppliers, quotes per id, negotiate). dry builds the exact Fo message for each call and sends nothing. live hands that message to Fo through a headless `claude -p` that may use only the Fo MCP tools (ask_fo, get_fo_reply, get_fo_conversation); every dry or live call dials FO_TEST_PHONE (or FO_TEST_PHONE_A/B/C per supplier) from ../.env, never a real supplier; calls run one at a time when suppliers share a phone. Live runs only after the human's yes; each call is logged to fo_log.jsonl.
- Cognee supplier memory is on by default (local, under buyline/data; `--no-memory` skips it, ~15 s faster). After a run it remembers each quote and the deal; the next order recalls them before any call and tells Fo to ask each supplier to beat their last price. The dashboard shows what it recalled.
- Supplier calls run in parallel, one Fo conversation each; every call card shows dialing, talking, quote in. `--prerun` runs only the quote calls and saves prerun.json; `--from-prerun` loads them so the demo does just the negotiation call live.
- Landed price: each quote carries shipping, fees and duty (a rate like 8% is applied to goods); ranking and the budget check use the landed total.
- Messy intake: `--intake FILE` (old invoice, spec sheet, email; `-` for stdin) or `--photo IMG`; the request text can override quantity and deadline.
- Haggle rules: code picks every number and Fo only says them. Target = the best lever (rival quote or the last price paid, from Cognee), capped by the user's `target price $X per meter` in the request and by the market soft line; open at 90% of target, raise only after they drop (half the gap, then shrinking), trial close, best and final at 3% over target (the soft line). The hard line is the budget per unit, capped by the market hard line, and never appears in Fo's prompt. After the call code accepts at or under the soft line, accepts and flags 'over our soft line' up to the hard line, and walks away above it; the dashboard line is `haggle.line` (`rounds[]` holds every round).
- Rounds: after the best supplier, the runner-up that can actually fill the order (minimum order, lead time) is called back with the best offer as the lever ("Supplier C offered $0.78, can you beat it?"), same truth-only rule. `--rounds N` (default 2); it stops when nobody improves. Use `--rounds 1` for a one-call demo.
- Market check: `market.py` (one Claude call with web search, ~20 s) runs in a thread beside the quote calls and puts `market: {low, typical, high, sources, soft_line, hard_line, line}` into state.json for the need card ("budget is below market" when the budget per unit is under the typical price). `--prerun` saves it in prerun.json and `--from-prerun` reuses it so the demo numbers stay put; `--no-market` skips it; on error the rival-quote and budget rules apply alone.
- Approve: `--until approve` leaves the PO waiting; the dashboard's Approve order / Not now buttons (serve.py, POST /approve and /not-now) or `--approve` / `--not-now` finish it with no Fo call. The PO goes by email only, to FO_TEST_EMAIL in dry and live; the dashboard shows the inbox masked.
- Order tracker: every PO lands in orders.json (ordered, shipped, delivered, ETA = order date + lead time, late flag past ETA). `--followup PO-0001` has Fo call the supplier's order desk and the answer moves the status and ETA; `--status PO-0001 shipped` marks it by hand. The dashboard's Orders card lists them.
- Morning briefing: at the approve stage `state.json` gets `briefing: {text, audio, voice}`. With `DEEPGRAM_API_KEY` in ../.env the text is spoken by Deepgram's Orpheus voice (aura-2-orpheus-en) into briefing.mp3 and `audio` names it; without a key `audio` is null and the dashboard shows the text. `python3 briefing.py` rebuilds it from state.json. Fo's call voice is never changed.
- `--until approve` stops before the PO; rerun without it to "approve". `--no-llm` uses regex extraction. `--out FILE` for a private state file.
- `python3 orchestrate.py --check` is the self-check (plan's A/B/C: C beats B because of B's 1000 minimum order; negotiates 0.88 -> 0.78).

## Buyline agent: supplier discovery and reasoning (agent.py)
- `--sourcing ai|mine|both` (default `book` = the replies file's suppliers, as before). `ai`: Claude (claude-opus-5-5 with web search) finds real candidate suppliers; code scores each on stock, business type, reachability and distance, skips the ones Fo can't reach or that likely don't stock the item, and records why. `mine`: your supplier book plus `--my-suppliers '[{"name":..,"phone":..}]'`. `both`: about half the slots for your suppliers, the rest for new ones.
- `--count auto|N`: auto scales with order value (under $1k: 3, under $10k: 4, under $50k: 5, else 6) and never exceeds the qualified candidates. `--max-suppliers N` or env `BUYLINE_MAX_SUPPLIERS` caps it for a demo. In stub mode the cap is the number of canned replies.
- Found businesses are display only. dry/live still dial `FO_TEST_PHONE*` and email `FO_TEST_EMAIL`, never a found supplier.
- Round 1 strategy: Claude picks which viable supplier to push and which real quote (or last paid price) to use as the lever, from options code built; code validates the pick and `haggle()` still sets every number. Fallback is the old rule.
- `state.json` gains `sourcing` (every candidate: id, name, source, score, status shortlisted/skipped, why, count_why, sources) and `events` (the timeline: actor agent/fo/you, kind think/act/result/ask, title, text, chips, call_index into `calls`). Each "think" text is written by Claude from code-built facts; a text quoting a dollar figure not in the facts, or the walk-away line, is replaced by the code-written line.
- `serve.py /start` accepts `sourcing_mode`, `target_count`, `my_suppliers`, `rounds` from the page (env `BUYLINE_SOURCING` sets the default mode). `/approve` accepts `{"supplier": id}` for the buyer's own pick, if it fits the order.
- Demo with a pre-run: `--prerun --sourcing ai` saves the found suppliers with the quotes, and `--from-prerun` replays them, so the page shows the same suppliers.
- New UI: `app.html` (open `http://localhost:8020/app.html`; `?preview` plays a labelled simulated run). See UI_HANDOFF.md.
